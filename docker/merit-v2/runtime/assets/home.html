About MERIT-ML

Metabolomics Evaluation of Readiness and Interoperability of Tabular Data for Machine Learning

MERIT-ML is a research software framework for assessing the machine-learning readiness of publicly deposited metabolomics tabular data. The current version focuses on studies available through the Metabolomics Workbench and evaluates whether deposited data matrices contain the minimum structural, label, sample-size, missingness, and annotation information needed to attempt supervised classification.

MERIT-ML was developed as part of an academic research project at the Centre for Digital Health, Indian Institute of Technology Bombay. The work was prepared by Shayantan Banerjee under the supervision of Prof. Pramod P. Wangikar, Department of Chemical Engineering and Centre for Digital Health, IIT Bombay.

The tool retrieves and summarizes publicly available repository-hosted data and metadata. It does not replace manual review, analytical validation, or biological interpretation of individual studies. MERIT-ML reports matrix properties, class-count support under the selected labels, and cohort-relative analytical alerts. It does not assign a universal ML-readiness score or certify predictive performance, biomarker validity, or external generalizability.

MERIT-ML is not affiliated with, endorsed by, or maintained by the Metabolomics Workbench. Users should cite the original deposited studies and the Metabolomics Workbench records when reusing data.

Small-n designs such as triplicate time-course, cell-culture, or 13C-tracing experiments may be scientifically valid for their original aim, but they remain limited for reliable supervised ML training, validation, and feature selection.

Cross-validation folds

Changes, for every matrix of the study: the count requirement of the readiness profile (requires ≥ k samples in every class), Class support (its fold target) and Cross-validation feasible. Alerts, annotation and metadata do not change.

default 5
Stratified k-fold cross-validation needs a sample of every class in every fold, so the count requirement is met when there are at least two classes and the smallest has at least k samples. A smallest class of m < k samples multiplies Class support by m ÷ k and makes cross-validation not feasible (✕); scikit-learn warns, and refuses the split when every class has fewer than k. Default 5. Allowed 2-10. Not the nearest-neighbour k of Class separability.
Structural

Changes the Structural score of every matrix of the study.

default 20
Number of distinct ML-eligible sample IDs at which Sample support reaches 100. Default 20. Fewer samples score proportionally lower.

Analytical QC

Changes the Low-information features score of every matrix of the study.

default 19
A feature is near-zero variance when its most common value is more than this many times as frequent as the second most common, and its distinct values are few (next value). Default 19 (95/5, caret nearZeroVar). Allowed 5-99.
default 10%
Distinct values of the feature as a percentage of the ML-eligible samples (missing included). Default 10 (caret nearZeroVar). Allowed 1-25.
default 1%
Features that are not flagged but vary by less than this percentage of their mean (CV), counted only for linear declared units without negative values. Not part of the score. Default 1. Allowed 0.1-5.
default 0.9
Two features whose Spearman correlation is above this value are a redundant pair; of each pair, the feature more correlated with all others counts as redundant. Default 0.90 (caret findCorrelation; Kuhn 2008). Allowed 0.80-0.99.
default 20
In the details of QC reproducibility, a feature passes when it is detected in more than 70% of the QC injections and its RSD across them is below this value (the headline median RSD does not use it). Default 20%; 30% is also common (Broadhurst et al. 2018). Allowed 10-40.
default 1.5
A sample is an outlier when its median value lies outside these fences of the ML-eligible samples' medians. Default 1.5 (Tukey's fences). Allowed 1.0-3.0; 3.0 flags only far-out samples.
Label structure and class support

The class definition (whole factor string, or chosen values and combinations) is set in the Label Structure tab. The number of folds k that Class support and Cross-validation feasible use is set under Cross-validation folds.

Readiness profile

Changes which matrices get an analytical review alert, and its tier, on the Overview; no score changes.

default 2%
A value of missing entries and zeros, low-information features, redundant features or outlier samples below this percentile of all valid matrices assessed here (default settings) is an extreme alert. Default 2.5: lower than 97.5% of the matrices. Cut-offs are kept for 2.5, 5, 7.5 and 10; another value is taken to the nearest of these.
default 10%
A value below this percentile but not below the extreme one is a low alert. Default 10: in the lowest tenth. Never stricter than the extreme tier (a smaller value is raised to it).
ML task readiness

Changes Class separability and the informational rows of every matrix. The classes are those chosen in Label Structure.

default 7
Each sample's k nearest neighbours (unit-agnostic rank distances) are looked at. Default 7 (Oh 2011, ten real datasets). Allowed 3-15.
default 3
Default 3 (Oh 2011); kept within 0 ≤ θ ≤ k/2 (Oh: the reasonable range). With k = 7 and θ = 3, the majority of neighbours must be in another class. A class needs at least k − θ + 1 samples.
default 0.05
Benjamini–Hochberg false discovery rate for the Kruskal–Wallis test of each feature across the classes. Default 0.05. Allowed 0.01-0.20.
